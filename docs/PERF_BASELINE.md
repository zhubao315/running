# RUNNING 性能基线（初值）

> 采集时间：2026-11-23T06:50:35Z
> 目标：https://zhubao315.github.io/running/
> 工具：Playwright + Chromium（Python），`scripts/perf_baseline.py`
> 状态：**基线初值**。单次线上测量，存在网络/CDN 波动；后续性能改动必须在同条件下复测，建议每组合跑 2–3 次取中位数。

## 测量矩阵

3 档视口（desktop 1440×900 / mobile-390 390×844 / mobile-360 360×800）× 2 种主题（dark / light）= 6 组。

指标口径：

- **LCP / CLS / INP**：PerformanceObserver 注入采集，页面加载后滚动触发交互。
- **JS(KB)**：所有 `.js` 资源的 transferSize 合计（含 Vite `type="module"` 脚本——其 `initiatorType` 为 `other`，故按后缀统计）。
- **JSON(KB)**：`.json` 资源合计（数据分片与汇总）。
- **3D 场景请求**：URL 含 `/scenes/` 或 `.scene` 的请求数。

## 关键发现

1. **3D 场景请求 = 0**：首屏没有加载任何 3D 场景，与路线图 P3「场景按需」一致，无需为 3D 做首屏优化。
2. **首屏 JS 615 KB**（传输体积）：其中 vendors ≈ 447 KB、activities 元数据 ≈ 111 KB、入口 ≈ 70 KB；这部分是历史元数据的固有成本，是否进一步优化须先有对比数据。
3. **CLS ≤ 0.0058、INP ≤ 22 ms**：布局稳定性与交互响应良好，无立即优化必要。
4. **LCP 波动明显**（1108–1996 ms）：desktop dark 1996 ms 而 mobile-390 light 1108 ms，主要受网络/冷启动影响，不是断点差异。对比时必须同条件多次取中位数。

## 使用规则

- 任何影响加载体积或渲染路径的改动（新增依赖、改分片策略、改 3D 触发方式），PR 中必须附本脚本复测的 JSON + 前后对比表。
- 不允许用「看着更快」验收；须与本文数据对比。
